# Definition of Done

Use only checks relevant to the task, but never claim completion without appropriate evidence.

A meaningful design implementation is done when:

1. **Intent** — the requested problem/change is satisfied without unintended scope expansion.
2. **System** — existing components/tokens/patterns were reused or intentionally extended; arbitrary parallel styling was not introduced.
3. **States** — relevant normal/extreme states were considered and implemented.
4. **Responsive** — relevant viewport/container behavior is defined and inspected.
5. **Accessibility** — relevant semantics, keyboard/focus, names/labels, contrast and state communication are addressed.
6. **Interaction** — behavior, feedback, errors, dismissal/validation and motion work as intended where applicable.
7. **Rendered evidence** — when implementation exists, inspect the rendered UI rather than trusting source/build success alone.
8. **Regression** — saved project rules and critical existing behavior were not violated.
9. **Uncertainty** — unresolved items are stated rather than hidden behind “done”.

Tiny changes require tiny verification; high-risk changes require deeper verification.
