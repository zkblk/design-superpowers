# Project Brain
Use an existing documentation structure if present. If the project lacks one and durable design knowledge is accumulating, use `.design/` minimally.

Suggested files/folders:
- `project.md` — product intent, constraints, source-of-truth links
- `rules.md` — confirmed project conventions/corrections
- `research/` — only research worth reusing
- `flows/` — durable task/flow models
- `decisions/` — important design decisions and alternatives
- `tests/` — hypotheses and validation evidence
- `case-study/` — raw evidence log, not polished marketing copy

Decision note: Problem → Evidence → Options → Decision → Why → Validation → Result (when known).
Do not create a persona/journey/flow because the UX process says so. Persist artifacts only when they reduce future uncertainty or preserve rationale.
